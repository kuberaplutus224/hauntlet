What configuration cannot fix (6)
  1. Some client behaviours are out of reach of config. How a client handles approvals is decided by the client. The most a bundle can do for an MCP server is: leave `autoApprove` empty, recommend not choosing "Always allow" for that server, and disable tools the task does not need.
  2. Steering is advisory. The model reads it and may still follow an injected instruction. A steering item is never described as enforcing anything.
  3. The sandbox does not cover built-in tools. By assumption A2, `sandbox.json` does not stop built-in file writes or web fetches.
  4. Hooks gate tool calls, not content. No documented hook can remove text from a page, file or tool result before the model reads it.
  5. A host allow-list cannot separate same-origin traps. In the range, task pages and trap canaries share one origin (`/c/<token>`). A host rule that allows the task allows the trap.
  6. A bundle loads only when the workspace is trusted. In an untrusted IDE or interactive CLI workspace, Kiro does not load steering or MCP config.
Assumptions
  • A1 `autoApprove` and `disabledTools` entry form. Kiro's MCP configuration page calls the entries "tool names"; its MCP security page's example lists `mcp_<server>_<tool>` IDs. This bundle uses plain tool names. Check that they took effect: the disabled tools are absent from Kiro's MCP panel for the server, and other tools still prompt.
  • A2 Built-in web fetch and the sandbox. The sandbox page does not list the built-in web fetch tool as covered, so no sandbox item is credited with blocking it.
  • A3 Loopback under `DEFAULT_BLOCKED`. The docs do not say whether `DEFAULT_BLOCKED` blocks loopback (127.0.0.1). A local range's canary endpoint is on loopback. Unverified.
  • A4 Hook commands inherit Kiro's environment. The hook pages say the command runs in the project root with event JSON on stdin; they do not say which environment variables it gets. The credential-egress guard (and the SECRETS rule's effect in the demo) relies on seeing the agent's environment. Unverified on Kiro.
  • A5 A sandboxed stdio MCP server can still write its own scratch workspace. If, with `mcpSandboxing` on, the range's server cannot write its fact log, the after run is reported as not exercised, never as clean.
